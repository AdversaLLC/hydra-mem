What the reading says

  • The book's agent-memory code is a list of what the write gate already stops: unconditional writes, the model's own replies stored as facts, self-scored confidence, provenance thrown away, and no way to say "I don't know". Take its ideas and none of its numbers: not one has a stated basis, and several contradict each other. V

  • Two of its retrieval code samples are wrong. One wraps the cosine in an absolute value, so opposite vectors look close. The other sets the rank-fusion constant to 0 where the standard is 60. My code uses a signed cosine and 60. V

  • The paper says a memory with limited room should keep recent material fine and old material coarse, in wider and wider time bands, and average old material rather than sample it. It proves this for forecasting a signal, not for finding a fact, and its experiments are three series and a linear learner. It tells me what to measure, not what to build yet. S U

  • The repositories mostly agree with choices already made: extracted memories wait for confirmation before they count (WeKnora, claude-mem), storage is plain SQLite, and nothing needs the cloud. The few things worth taking are small. S

The plan

Every item is written test first, with the test watched failing before the code exists. Every guard added gets a deliberate break in tools/mutation_check.py.

Phase 1. Make what exists honest

Built 22 Oct 2026, in this order, test first. Each guard has a deliberate break that the tests must catch.
  1. 1.1

    Say when an answer is degraded

    If the vector search fails, results carry degraded and the text says it is keyword-only. No evidence, degraded and error stay three different answers.

    Check: break the vector index in a test; the JSON and the text both say so.

    Built. Results carry degraded, the text says keyword-only, and an empty degraded answer is never read as "nothing stored". 12 tests.

    V our own incident S basic-memory fails loudly
  2. 1.2

    Handles everywhere

    Packed text shows #handles. memory_get and /v1/node accept them. A clashing handle is reported as ambiguous, with the candidates, instead of missing.

    Check: the block fits at least the measured number of notes at 400, 800 and 1,500 tokens; a forced clash is reported.

    Built. Handles in packed text, memory_get, /v1/node and memory_supersede. A clash lists only notes the caller can read. 12 tests.

    V measured on your notes
  3. 1.3

    Show which search found each hit

    Each result says keyword, vector or both, so a reader can weigh a keyword-only hit differently.

    Check: one note findable only by words, one only by meaning.

    Built. Each hit shows kw, vec, both or graph. 4 tests.

    V the book's own lab found this useful
  4. 1.4

    Search by tag

    tag= finds notes by concept, file name or session-summary.

    Built. Whole-tag match, ignoring case, applied before the candidate cut. 9 tests.

    S rad-mem searches by concept and file
  5. 1.5

    Read-only hints on the read tools

    Mark the search, timeline, fetch and context tools read-only in the MCP list, so a client stops asking permission for reads while writes still ask.

    Built. The eight read tools are marked read-only and supersede is marked destructive. A test runs every read and proves the notes, links and audit chain are unchanged. 6 tests.

    V claude-mem's source does this for the same reason
  6. 1.6

    Neighbour hints when writing

    A write returns near-but-not-identical notes the writer is allowed to see. When a refused duplicate differs in a number or a negation, it says so, so the writer supersedes the old note instead of retrying. No model involved.

    Check: a note that differs only by "not" is flagged; a private note never appears as a neighbour.

    Built, and the check changed. On your notes the trigram band in the plan finds nothing: the median nearest neighbour scores 0.01, and two notes on the same fact score 0.04 and 0.22. The hints use content-word overlap of 0.25 or more instead. The work also fixed a leak: another agent's private note made a write come back as a duplicate with its id, and a trashed note blocked saving the same text again. 51 tests.

    U two readers reached this independently
  7. 1.7

    Embedder fingerprint

    At start the vector service embeds a fixed canary text and compares it with the stored copy. A mismatch turns the vector side off and says why. doctor lists notes that have no vector yet.

    Built, with two extra checks. The canary is pinned beside the vectors. At start three stored notes are also re-embedded and compared, and doctor counts the embedders in the vectors table. On your store 10 of 297 active notes have no vector today. 42 tests.

    V the Ollama mix-up S the book says mixed embedders fail silently
  8. 1.8

    Scale guard

    stats and doctor warn at 8,000 active notes (reads are slowing) and again at 20,000 (older notes stop appearing), and the results say when a scan hit that cap. The benchmark uses a new query every time so the cache cannot flatter it.

    Built. Warnings at 8,000 and 20,000 notes in stats, doctor and the viewer; results carry scan_capped. Two cut bugs fixed: past the cap the timeline dropped the newest notes, and the context cut to the newest 3,000 before checking who may read them. 20 tests.

  9. 1.9

    A standing "must never come back" suite

    Out-of-scope, expired, trashed, superseded and wrong-lane notes, plus decoy notes that read like instructions, must not come back from any read path.

    Built. Eight kinds of hidden note against six agents through every read path, the MCP text and the admin routes, plus a test that fails when a route is added without a place in it. It found two problems, both fixed: stats counted every agent's private notes, and owner-approved notes were missing from the session list. One limit remains: an id suffix hints that a hidden note with the same title exists. 21 tests.

    U neither book chapter tests this

Phase 2. Measure before deciding

Build the instruments, then use the service for a few weeks.
  1. 2.1

    A usage log, counts only

    For each read: which operation, which agent, how many notes, tokens served, tokens had everything been fetched, abstained or degraded, milliseconds, and the age band of what was fetched. No text and no ids. Owner-only /v1/usage, a memctl census, and a savings card with its baseline written on it and capped below 100%. It is for review and never feeds ranking, because an agent could inflate it.

    S the token-savings dashboard U two readers
  2. 2.2

    memctl eval

    Answerable, unanswerable and must-not-retrieve questions; recall at 5, MRR, an abstention table and a paired bootstrap. The 0.25 and 0.34 floors were set on the same 50 questions, so check them with a 5-fold split.

    U
  3. 2.3

    Choose the decay from data

    Test whether usefulness falls with age like a power or like an exponential before building any age banding. The paper's premise is that the right timescale is unknown.

    S paper S claude-mem's old docs use an unexplained 30-day half-life
  4. 2.4

    SQL paging for the read path

    Do it when the median read passes 100 ms or active notes pass 3,000, whichever comes first.

Phase 3. Needs your decision

Each changes what the service trusts or downloads.
  1. 3.1

    Procedure notes

    An owner-approved kind with applies-when, steps, a stop condition and links to its evidence. Shown as labelled data. It keeps plain applied, worked and failed counts that never touch confidence, and it expires until re-approved. Agents can only propose into probation. Nothing is learned from transcripts.

    U a procedure steers behaviour, so it has the highest bar of any kind
  2. 3.2

    A reranker experiment

    Score (query, note) pairs to sharpen abstention or ordering, and keep it only if the paired test on the 36 + 14 questions shows a gain. Needs a download of about 80 MB.

  3. 3.3

    A reversible archive tier

    For old, never-fetched notes. Triggered when active notes pass about 2,000 or the usage log shows a long unread tail.

  4. 3.4

    Related notes

    A read of typed neighbours, as basic-memory builds context around a note.

    S

What I would not do

Each of these came up in the reading and loses on the reasons below.

IdeaWhy not
A semantic query cacheIt needs the query embedding first, which is most of the cost it would save, and a paraphrase hit can cross scopes. The exact cache keyed on scope and audit state stays.
Capturing and compressing with a model inside the serviceText that reaches the model can steer what gets stored. The book's own code shows the result.
Standing-instruction memories that always loadAn agent-writable instruction is an injection route. Your CLAUDE.md is the owner-controlled place for that.
Learning procedures from transcripts, or scoring them by a moving averageOne conversation could write advice every user receives. The average measures nothing a control group would.
Hosted featuresclaude-mem's hosted observer, TrueMemory's query expansion through a model and its default telemetry, and basic-memory's cloud all send data off the machine.
Community scope, and a graph index for speedThere is one owner, and exact scanning is fine at this size.
Any threshold taken from a bookNone had a stated basis. Mine were measured on your questions.
Installing the two forked agent collectionsThey are not about memory, and their always-loaded descriptions cost context in every session.

Decisions for you

  1. Phase 1 is built. Restart the memory service to use it (below).
  2. Procedure notes (3.1): yes, no, or after the usage log has run.
  3. The reranker experiment (3.2): is a non-generative transformer within your "no language model" rule, and may I download the model?

Before using it

The memory service runs old code or is stopped. Start it with python3 -I memctl serve --port 8765 (Ctrl-C first if it is running). The first start pins the embedder fingerprint beside your vectors and checks three stored notes against it.
